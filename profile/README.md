# team-memory-system

에이전트와 하는 대화를 각자의 기억 서버에 모으고, 팀원끼리는 서로의 기억에 질문만
할 수 있게 열어 두는 자기호스팅 기억 시스템입니다.

## 어떤 구조인가

```
이 컴퓨터의 수집기   ─────────────────────────────────────▶ 내 기억 서버(Honcho)
내 다른 컴퓨터의 수집기 ── Cloudflare Tunnel ── gate(서버 token) ─▶ 내 기억 서버
팀원의 에이전트     ── Cloudflare Tunnel ── Google 로그인 ── gate ─▶ chat 하나
정한 폴더의 대화만   ─────────────────────────────────────▶ 회사 공용 기억 서버

내 기억 서버 ─▶ PostgreSQL · 임베딩 Ollama(Qwen3 4B) · 대화 정리 모델(구독 게이트웨이)
```

- **사람마다 기억 서버가 하나, 데이터베이스가 하나입니다.** 컴퓨터를 여러 대 쓰더라도 대화는
  모두 자기 서버 한 곳으로 모입니다. 서버를 둔 컴퓨터 말고는 수집기만 깔고 서버 주소를 줍니다.
- **다른 서버에도 쌓을 수 있습니다.** 고른 프로젝트에서 한 대화만 회사 공용 서버 같은 다른 서버에도
  함께 쌓입니다. 내 서버에는 지금처럼 모든 대화가 쌓입니다.
- **팀원끼리 데이터베이스를 공유하지 않습니다.** 공유되는 것은 MCP 도구 `chat` 하나뿐입니다.
  팀원은 Google로 로그인해 질문하고 답을 받을 뿐, 원문 메시지를 읽지 않습니다.

## 조직 저장소

| | 무엇인가 | 어디에 설치하나 |
|---|---|---|
| [honcho-agent-bridge](https://github.com/team-memory-system/honcho-agent-bridge) | 팀 메모리 앱, 수집기, 설치기, 에이전트 플러그인 (MIT) | 에이전트를 돌리는 컴퓨터마다 |
| [honcho-selfhost](https://github.com/team-memory-system/honcho-selfhost) | 기억 서버. 공식 Honcho 서브모듈에 자체 패치를 적용하는 배포 저장소 (AGPL-3.0) | 서버를 둘 컴퓨터 |
| [subscription-gateway](https://github.com/team-memory-system/subscription-gateway) | Codex·Claude 구독 계정을 모델 API로 바꾸고, 한도에 걸리면 다음 계정으로 넘기는 공용 게이트웨이. 다른 프로젝트에서도 따로 씁니다 (AGPL-3.0) | 기억 서버를 두는 컴퓨터 |

직접 설치하는 것은 **`honcho-agent-bridge` 하나**입니다. 기억 서버를 이 컴퓨터에 두면 설치
과정이 나머지 둘을 내려받습니다. 어느 커밋을 가져올지는 플러그인 안의
`server/honcho-source.json`, `server/gateway-source.json`에 고정돼 있어서, 원본 저장소의
최신 변경이 설치에 저절로 들어오지 않습니다.

# 설치

> **에이전트에게.** 이 문서로는 "먼저 설치할 것"과 "플러그인 설치"까지만 합니다. 플러그인을 깐 뒤에는
> 더 진행하지 말고 사용자에게 아래 문장을 그대로 전하세요. 그다음 안내는 플러그인의 설치 스킬이
> 정해진 문장으로 합니다.
>
> - Claude Code: "플러그인을 설치했습니다. `/reload-plugins`를 입력한 다음 `/memory-setup`을 입력하세요. 거기서부터 설치를 안내합니다."
> - Codex: "플러그인을 설치했습니다. Codex를 새 세션으로 연 다음 `$setup-memory`를 입력하세요. 거기서부터 설치를 안내합니다."

## 먼저 설치할 것

플러그인을 깔기 전에 아래 프로그램부터 있어야 합니다. 에이전트에게 설치를 맡기면 기억 서버를 어디에
둘지 고른 뒤 이것부터 확인하고, 없으면 공식 설치 방법으로 설치할지 묻습니다. 앱의 **시작하기** 화면 첫 단계도 같은
확인입니다.

| 프로그램 | 언제 필요한가 | macOS | 윈도우 |
|---|---|---|---|
| **Claude Code 또는 Codex** | 항상 | 각 제품의 설치 안내 | 각 제품의 설치 안내 |
| **Node.js 18 이상** | 항상. 플러그인과 앱이 Node로 돕니다 | [nodejs.org](https://nodejs.org) LTS 설치 파일, 또는 `brew install node` | `winget install --id OpenJS.NodeJS.LTS -e` |
| **git** | 항상. 플러그인 설치와 서버 소스 받기에 씁니다 | `xcode-select --install` | `winget install --id Git.Git -e` |
| Docker Desktop, Ollama | 이 컴퓨터에 기억 서버를 만들 때 | 없으면 앱이 설치합니다 | 없으면 앱이 설치합니다 |

## 그다음: 플러그인 설치

지금 쓰는 에이전트 한 곳에만 설치합니다. 대화 쌓기 설정을 적용하면, 고른 에이전트 중 플러그인이
없는 쪽(Codex 또는 Claude Code)에도 앱이 플러그인을 넣습니다.

**Claude Code**
```sh
/plugin marketplace add team-memory-system/honcho-agent-bridge
/plugin install honcho-agent-bridge@honcho-agent-bridge
```

**Codex**
```sh
codex plugin marketplace add team-memory-system/honcho-agent-bridge
codex plugin add honcho-agent-bridge@honcho-agent-bridge
```

이미 깔려 있으면 새 버전으로 올립니다.

```sh
claude plugin marketplace update honcho-agent-bridge
claude plugin update honcho-agent-bridge@honcho-agent-bridge
codex plugin marketplace upgrade
codex plugin add honcho-agent-bridge@honcho-agent-bridge
```

설치한 뒤 Claude Code는 `/reload-plugins`, Codex는 새 세션을 엽니다.

## 그리고: 팀 메모리 앱 열기

Claude Code에서 `/memory-setup`, Codex에서 `$setup-memory`를 실행하면 에이전트가 앱을 열어
줍니다. 직접 열려면 플러그인 폴더에서 이렇게 합니다.

```sh
node scripts/cli.mjs ui open        # http://127.0.0.1:4180
```

앱은 이 컴퓨터에서만 열립니다. 처음 열면 **시작하기** 화면에서 기억 서버를 어디에 둘지 둘 중
하나를 고릅니다. 에이전트에게 설치를 맡겨도 같은 두 가지를 묻습니다.

| 선택 | 하는 일 | 필요한 것 |
|---|---|---|
| **이 컴퓨터에 기억 서버 만들기** | 이 컴퓨터에 기억 서버를 설치하고, 이 컴퓨터의 Claude Code·Codex 대화를 모은다. 내 다른 컴퓨터의 대화도 나중에 이 서버로 모을 수 있다 | 디스크 몇 GB, Codex나 Claude 구독. Docker와 Ollama는 앱이 설치합니다 |
| **다른 컴퓨터의 기억 서버에 연결하기** | 내 기억 서버가 있는 다른 컴퓨터로 이 컴퓨터의 Claude Code·Codex 대화를 보낸다 | 그 컴퓨터의 서버 → 공유에서 받은 주소와 서버 토큰 |

고른 쪽의 할 일이 체크리스트로 보이고, 단계마다 지금 된 것과 안 된 것을 실제 상태로 알려 줍니다.

다음은 처음에 묻지 않고, 준비를 마친 뒤 필요할 때 켭니다.

- **팀원 기억 연결** (팀 메뉴): 팀원에게 받은 팀 주소로 팀원 기억에 묻습니다. 어느 쪽을 골랐든
  할 수 있습니다. [팀원 기억 연결](#팀원-기억-연결)을 보세요.
- **공유** (이 컴퓨터에 기억 서버를 만들었을 때): 서버 → **공유**에서 켭니다. 켜면 내 다른 컴퓨터의
  대화도 이 서버에 쌓이고, 팀원이 이 기억에 묻습니다. 팀원은 팀 → **내 기억 공유**에서 더합니다.
- **다른 서버에도 쌓기** (기억 설정 메뉴): 고른 프로젝트의 대화만 다른 기억 서버에도 쌓습니다.
- **ChatGPT 기록 가져오기** (기억 설정 메뉴): ChatGPT에서 내보낸 대화를 내 기억 서버에 넣습니다.

## 이 컴퓨터에 기억 서버 만들기

앱의 **서버** 화면에서 위에서부터 차례로 누릅니다.

| 단계 | 앱이 하는 일 | 내가 할 일 |
|---|---|---|
| 1. 무엇을 설치할지 보기 | 받을 것과 바꿀 것을 한글로 보여 줍니다. 아직 아무것도 설치하지 않습니다 | 읽기 |
| 2. Docker와 Ollama 준비 | 없으면 받아서 설치합니다. Docker Desktop은 `/Applications`에, Ollama는 앱 폴더에 둡니다 | Docker 창이 뜨면 약관 동의, 권장 설정, macOS 암호 입력 |
| 3. 구독 게이트웨이 설치 | 게이트웨이를 받아 설치하고, 로그인할 때 자동으로 켜지게 합니다 | 없음 |
| 4. 게이트웨이에 구독 계정 로그인 | 로그인 창을 엽니다 | Codex나 Claude 계정으로 로그인 |
| 5. 기억 서버 준비 | 게이트웨이 주소·키·모델을 서버 설정에 쓰고, 임베딩 모델(Qwen3-Embedding 4B, 약 2.5GB)을 받습니다 | 없음 |
| 6. 시작 | 서버 이미지를 만들고 켭니다. 처음에는 몇 분 걸립니다 | 없음 |

끝나면 **끝에서 끝까지 점검**을 눌러 서버, 임베딩, 게이트웨이까지 모두 답하는지 확인합니다.
그다음 [대화 쌓기](#대화-쌓기)에서 **이 컴퓨터 서버**를 골라 이 컴퓨터의 대화를 모읍니다.

알아 둘 것:

- **Docker Desktop 라이선스.** 개인, 교육, 비영리 오픈소스, 작은 회사(직원 250명 미만이고
  연 매출 1천만 달러 미만)에서는 무료입니다. 그보다 큰 회사나 정부 기관에서는 유료 구독이
  필요합니다.
- **윈도우**에서는 Docker 설치 때 관리자 허락 창에서 **예**를 눌러야 하고, WSL 2 때문에 다시
  시작하라고 할 수 있습니다. 다시 켠 뒤 앱을 열고 이어서 준비를 누릅니다.
- **재부팅한 뒤에는** 모두 스스로 다시 뜹니다. 게이트웨이와 임베딩 감시 프로그램은 로그인할 때
  켜지게 등록돼 있고, 기억 서버는 Docker와 함께 올라옵니다. 임베딩 감시는 앱이 받은 Ollama도
  함께 띄웁니다.
- **포트.** 기억 서버는 보통 `127.0.0.1:8001`(API)과 `127.0.0.1:4173`(앱이 쓰는 도구 설정 API)을 씁니다.
  화면은 팀 메모리 앱(`127.0.0.1:4180`) 하나이고, 4173을 브라우저로 열면 앱으로 넘어갑니다.
  이미 쓰고 있으면 다음 빈 번호를 고르고, 앱과 수집기도 그 주소를 씁니다. 모두 이 컴퓨터
  안에서만 열립니다.
- **기억을 바꾸는 도구는 꺼진 채로 시작합니다.** 에이전트가 쓰는 MCP 도구 31개 중 기억을 쓰거나
  지우는 도구는 꺼져 있고, 찾는 도구만 켜져 있습니다. 기억 설정 → **MCP 도구**에서 **찾기 도구**와
  **바꾸기·지우기 도구**를 묶음으로 켜고 끄고, **하나씩 켜고 끄기**에서 도구마다 바꿉니다.

### 공유: 내 다른 컴퓨터와 팀원에게 열기

서버 → **공유**에서 켭니다. 켜면 서버의 Docker 안에서 세 가지가 함께 돕니다.

- **gate.** 내 다른 컴퓨터가 보내는 대화는 서버 토큰이 있어야 들어옵니다.
- **팀원 MCP(`/mcp`).** 팀원의 에이전트는 Google로 로그인해 들어와 `chat` 하나로 묻습니다. 묻는 범위는
  내 기억 하나로 고정되고, 묻는 것마다 그 사람의 이메일과 함께 기록됩니다.
- **Cloudflare Tunnel.** 위 둘을 `https://<이름>.<도메인>` 주소로 밖에 엽니다. 그 주소 앞에서
  Cloudflare Access가 Google 로그인을 확인합니다. Cloudflare는 팀 관리자가 처음 한 번 설정합니다.

공유를 켜는 길은 둘입니다.

**가. 팀 관리자: 팀 만들기.** 도메인이 있는 Cloudflare 계정을 가진 한 사람이 합니다.

1. Cloudflare에서 한 번만 준비합니다.
   - 그 계정에 도메인이 올라가 있어야 합니다.
   - Zero Trust를 켜고, Settings → Authentication → Login methods에 Google을 넣습니다.
   - API token을 하나 만듭니다. 권한은 Account → Cloudflare Tunnel → Edit,
     Account → Access: Apps and Policies → Edit,
     Account → Access: Organizations, Identity Providers, and Groups → Read,
     그리고 그 도메인에 Zone → DNS → Edit, Zone → Zone → Read입니다.
2. 서버 → 공유 → **팀 만들기**에 Cloudflare API token과 내 Google 이메일을 넣고 **팀 만들기**를 누릅니다.
   앱이 Tunnel, 주소(`memory.<도메인>`), Access 앱, 들어올 수 있는 사람 목록을 만듭니다. 이미 있는 것은
   그대로 둡니다.

**나. 팀원: 초대 코드로 열기.** 관리자에게 받은 **초대 코드**를 서버 → 공유 → **초대 코드로 열기**에
넣고 **열기**를 누릅니다. 초대 코드 하나면 됩니다.

**팀원 관리 (관리자).** 팀 → **내 기억 공유**에서 합니다.

- **팀원 더하기**에 그 사람이 Google에 로그인하는 이메일을 넣습니다. 그 사람도 자기 기억을 공유하면
  **이 사람도 자기 기억을 공유**를 켭니다. 그러면 그 사람 서버의 주소(`memory-<이름>.<도메인>`)가 생기고,
  초대 코드가 한 번만 나옵니다. 초대 코드에는 Tunnel token이 들어 있으니 비공개로 전합니다.
- **팀 주소 복사**로 받은 글을 묻기만 하는 팀원에게 줍니다. 비밀이 없는 주소 목록입니다.
- 더한 사람은 팀에서 공유를 켠 모든 사람의 기억 전체에 `chat`으로 물을 수 있습니다.
- Zero Trust 무료 요금제는 50자리입니다. 사람마다 처음 로그인할 때 한 자리를 쓰고, 같은 계정의 다른
  Access 앱과 자리를 나눠 씁니다. 목록에서 빼도 자리는 남고, Zero Trust의 사용자 목록에서 지워야
  비워집니다.

**서버 토큰.** 서버 → 공유의 **서버 token 복사**로 받은 값을 다른 컴퓨터의 기억 설정 → 대화 쌓기에
넣습니다. **서버 token 바꾸기**를 누르면 지금 토큰을 쓰는 컴퓨터는 모두 끊기니, 새
토큰을 다시 넣어야 합니다.
**공유 끄기**를 눌러도 토큰과 Cloudflare 설정은 남겨 두어서, 다시 켜면 다른 컴퓨터와 팀원 설정을
고칠 필요가 없습니다. **밖에서 확인**은 밖에서 닿는지, Access가 막는지, 토큰이 틀렸는지 구분해
알려 줍니다.

Tunnel을 이미 직접 만들어 두었다면 서버 → 공유의 접힌 **직접 만든 Tunnel로 켜기**를 씁니다.
그 Tunnel의 서비스 주소는 `http://gate:8010`이어야 합니다.

## 대화 쌓기

앱의 **기억 설정 → 대화 쌓기**에서 켭니다. 서버를 이 컴퓨터에 만들었다면 **이 컴퓨터 서버**를 고르고,
모을 에이전트와 내 이름을 정한 뒤 마지막 단계에서 **적용**을 누르면 됩니다. 아래는 **다른 컴퓨터의
기억 서버에 연결하기**를 골랐을 때입니다. 이 컴퓨터에는 수집기만 둡니다.

1. **서버를 둔 컴퓨터에서 공유를 켭니다.** [공유](#공유-내-다른-컴퓨터와-팀원에게-열기)를 보세요.
2. **이 컴퓨터 앱의 기억 설정 → 대화 쌓기**에서 기억 서버 주소(서버 컴퓨터의 공개 주소)와 서버 토큰을
   넣고, 모을 에이전트를 고른 뒤 마지막 단계에서 **적용**을 누릅니다.
   - 토큰이 틀리면 "서버가 이 토큰을 받지 않습니다"라고 알려 줍니다. Cloudflare Access가 막으면 그렇게
     따로 알려 줍니다. 공유를 직접 만든 Tunnel로 켠 서버라면 그 서버의 Access 서비스 토큰을 넣습니다.
3. **에이전트를 다시 시작합니다.** Claude Code는 `/reload-plugins`, Codex는 새 세션을 열고
   훅 "Syncing codex conversation to personal memory"를 승인합니다(`/hooks`에서도 됩니다).
4. **시작하기** 화면의 **첫 기억 확인**이 이 컴퓨터에서 한 대화가 서버에 들어왔는지 보여 줍니다.

토큰과 비밀은 채팅에 붙여 넣지 마세요. 앱은 이 값들을 명령행이 아닌 환경변수로만 넘기고,
화면과 기록에 다시 보여 주지 않습니다.

### 다른 서버에도 쌓기

고른 프로젝트에서 한 대화만 회사 공용 기억 서버 같은 다른 서버에도 쌓습니다. **기억 설정 → 다른
서버에도 쌓기**에서 네 단계로 더합니다.

1. **서버**: 이름, 서버 주소, 그 서버의 토큰을 넣습니다.
2. **프로젝트**: 이 컴퓨터의 Claude Code·Codex 대화가 열린 폴더들이 프로젝트로 보입니다. 저장소 안의
   폴더는 그 저장소로 묶입니다. 쌓을 프로젝트를 고르고, 목록에 없는 폴더는 **다른 폴더 더하기**로
   고릅니다.
3. **지난 대화**: **지금부터만** 쌓을지, 날짜를 정해 **지난 대화도** 쌓을지 고릅니다.
4. **확인**: 고른 것을 보고 **더하기**를 누릅니다.

- 고른 프로젝트 안에서 연 에이전트 대화만 갑니다. 그 밖의 대화와 ChatGPT에서 가져온 기록은 가지
  않습니다. 한 대화는 처음 열린 폴더로 판단합니다.
- 회사 서버가 꺼져 있어도 내 서버로 가는 것은 멈추지 않습니다. 못 보낸 대화는 기다렸다가
  이어서 보내고, 같은 대화가 두 번 들어가지 않습니다.
- 지난 대화는 한 번에 500개까지 쌓습니다. 남으면 그 서버의 **지난 대화 쌓기**를 누르면 이어서
  쌓습니다.
- 에이전트가 기억을 찾을 때는 내 서버만 봅니다.

## 팀원 기억 연결

팀원이 열어 준 기억에 `chat` 도구로 묻습니다. 플러그인만 있으면 언제든 연결하고, 여러 팀원의 기억을
함께 연결할 수 있습니다.

1. **팀 → 팀원 기억 연결**에 팀원에게 받은 팀 주소를 붙여 넣고 **Claude Code·Codex에 연결**을
   누릅니다. 팀원 서버마다 `team-<이름>`이라는 MCP 서버가 Claude Code와 Codex에 더해집니다.
2. **한 번 로그인합니다.** Claude Code는 `/mcp`에서 `team-<이름>`을 고르고 Authenticate를 누르고,
   Codex는 같은 화면의 **Codex 로그인**을 누릅니다. 브라우저가 열리면 팀에 등록된 Google 계정으로
   로그인합니다. 로그인 정보는 Claude Code와 Codex가 각자 보관합니다.
3. 에이전트는 `team-<이름>` 서버의 `chat`으로 묻습니다. 대화 쌓기를 켜 두었다면 내 기억 도구는
   그대로 남습니다.

## 터미널로 하고 싶으면

앱이 하는 일은 모두 CLI로도 됩니다. 플러그인 폴더(Claude Code는
`~/.claude/plugins/cache/honcho-agent-bridge/honcho-agent-bridge/<버전>/`)에서 실행합니다.

```sh
node scripts/cli.mjs server plan    --profile personal   # 무엇이 바뀌는지
node scripts/cli.mjs server prepare --profile personal   # Docker·Ollama·게이트웨이 설치. 로그인 전이면 멈춤
node scripts/cli.mjs gateway open                        # 게이트웨이 화면에서 로그인
node scripts/cli.mjs server prepare --profile personal   # 로그인한 뒤 다시
node scripts/cli.mjs server start   --profile personal
node scripts/cli.mjs server verify  --profile personal
node scripts/cli.mjs setup apply --agents codex,claude --user-peer <내 이름> [--honcho-url <주소>]
CLOUDFLARE_API_TOKEN=… node scripts/cli.mjs server share enable --cloudflare --email <내 Google 이메일>
node scripts/cli.mjs server share join --invite-file <초대 코드 파일>
node scripts/cli.mjs teammates add <이메일> [--share <이름> --invite-out <파일>]
node scripts/cli.mjs teammates connect <이름> <주소>
HONCHO_TARGET_API_TOKEN=… node scripts/cli.mjs target add company --url <주소> --folders <폴더들>
```

토큰은 명령행 인자로 주면 거부합니다. 위처럼 환경변수로 줍니다.

## 문제가 생기면

Claude Code에서 `/memory-doctor`, Codex에서 `$setup-memory`로 진단을 요청하세요. 앱의
기억 설정 → **대화 쌓기** 화면의 **점검에서 걸린 것**에도 무엇이 걸렸고 무엇을 누를지 나옵니다.

```sh
node scripts/cli.mjs detect   # 이 컴퓨터에 무엇이 있는지
node scripts/cli.mjs doctor   # 무엇이 잘못됐는지
```

자주 걸리는 것:

- **게이트웨이에 로그인했는데 모델이 없다고 나옴:** 예전에 설치한 게이트웨이의 프로그램이
  남아 포트를 잡고 있을 수 있습니다. 컴퓨터를 다시 시작하거나, 게이트웨이 화면에서 알려 주는
  프로그램을 끄세요.
- **팀원 기억에 로그인했는데 막힘:** 그 Google 이메일이 팀 목록에 있는지 관리자에게 확인합니다.
  회사 계정처럼 다른 Google 계정으로 로그인하지 않았는지도 봅니다.
- **Codex 대화가 안 모임:** 새 세션에서 훅 승인을 했는지 확인합니다.

## 지금 안 되어 있는 것

숨기지 않고 적습니다.

- **Google 로그인을 거쳐 팀원 기억에 묻는 것은 아직 사람이 처음부터 끝까지 해 보지 못했습니다.**
  실제 Cloudflare Tunnel로 다른 컴퓨터가 서버에 닿는 것과, gate 뒤의 팀원 MCP가 `chat`에 답하는 것까지는
  확인했습니다.
- **묻는 범위를 사람이나 프로젝트별로 나눌 수 없습니다.** 팀에 더한 사람은 팀에서 공유를 켠 모든
  사람의 기억 전체에 `chat`으로 물을 수 있습니다.
- **윈도우의 Docker 자동 설치는 아직 실제 기기에서 시험하지 못했습니다.** macOS는 Docker와
  Ollama가 없는 컴퓨터에서 처음부터 설치해 대화 정리·검색·묻기까지 확인했습니다.
- **기억 서버 자체의 인증은 꺼져 있습니다** (`AUTH_USE_AUTH=false`). 서버는 이 컴퓨터 안에서만
  열리고, 밖에서 오는 요청은 gate의 서버 토큰과 Cloudflare Access(Google 로그인)가 지킵니다.

## 기억은 어디에 있나

대화 원문과 정리된 기억은 **기억 서버를 둔 컴퓨터의 PostgreSQL**에만 있습니다. 다른 서버에도
쌓기로 서버를 더했다면 고른 프로젝트의 대화는 그 서버에도 있습니다. 이 조직의 저장소에는 코드만 있고,
토큰과 설정은 각자 컴퓨터의 비공개 파일에 있습니다.
